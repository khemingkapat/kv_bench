# LMCache Local Replication & Profiling Plan

This plan outlines a 4-phase approach to benchmark, profile, and deeply understand the core architectural claims of LMCache (Prefix Reuse, Layer-wise Pipelining, and Context Disaggregation) on a single consumer GPU configuration (e.g., GTX 1660 Super with 6GB VRAM).

---

## Phase 1: Establish the Baseline (Measuring Raw TTFT)

### Objective
Measure the standard, unoptimized inference performance of an LLM to establish the ground-truth Time to First Token (TTFT) when processing long prompts from scratch.

### Tasks for Agent
1. **Model & Framework Setup:**
   * Configure a lightweight model (e.g., `Qwen/Qwen2.5-0.5B`) using a standard serving engine (e.g., vLLM or Hugging Face transformers) without LMCache enabled.
   * Restrict maximum VRAM allocation to fit comfortably within the 6GB limit.
2. **Workload Generation:**
   * Create a script to generate a long synthetic prompt context (e.g., 2,000 to 4,000 tokens) followed by a short generation instruction (e.g., 64 new tokens).
3. **Metrics Tracking:**
   * Implement accurate timing code to separate **Time to First Token (TTFT)** from the **Decode/Generation Time**.
   * Run the test 3-5 times to gather a clean baseline average for TTFT and total generation throughput.
4. **Output:** 
   * Save the baseline metrics to `results/baseline_phase1.json`.

---

## Phase 2: Micro-benchmarking Prefix Reuse (Memory Loading)

### Objective
Enable LMCache to verify its ability to store and reuse KV caches from system RAM, proving that the GPU can bypass the heavy "Prefill" mathematical computation on matched prefixes.

### Tasks for Agent
1. **LMCache Integration:**
   * Update the configuration to launch the engine with LMCache enabled, setting the storage backend to local CPU memory (RAM) or local disk.
2. **The Cold Run Test:**
   * Send the long prompt context created in Phase 1 for the very first time.
   * Verify via logs that LMCache successfully serializes and offloads the calculated KV cache blocks to the storage backend.
3. **The Warm Run Test:**
   * Send a *second* request that reuses the exact same long context prefix but appends a completely different question/instruction at the end.
   * Record the new TTFT and Decode times.
4. **Evaluation:**
   * Compare the Cold Run TTFT against the Warm Run TTFT. Verify that the Warm Run TTFT shows a significant reduction (e.g., >30% speedup), proving the prompt computation was bypassed.
5. **Output:**
   * Save the results to `results/lmcache_phase2.json`.

---

## Phase 3: Hardware Profiling Layer-wise Pipelining

### Objective
Profile the hardware execution timeline during a Warm Run to verify LMCache's core engineering claim: overlapping GPU attention computation with PCIe memory transfers (asynchronous pipelining).

### Tasks for Agent
1. **Profiler Setup:**
   * Integrate a hardware profiling tool into the test runner script. Use the PyTorch Profiler (`torch.profiler.profile`) or prepare a command line string to run the warm benchmark under NVIDIA Nsight Systems (`nsys profile`).
2. **Timeline Collection:**
   * Configure the profiler to capture both **CUDA compute kernels** (e.g., Attention, FeedForward execution) and **Memory Copies (Memcpy HtoD)** across the PCIe bus.
   * Run the Warm Run benchmark from Phase 2 with active tracing enabled for a small subset of generation steps.
3. **Verification Logic:**
   * Analyze the trace timeline to locate the layer execution pattern.
   * Verify whether a "staircase" or overlapping behavior is visible—specifically checking if `Memcpy` operations for Layer $N+1$ are executing concurrently while the GPU is processing the compute kernels for Layer $N$.
4. **Output:**
   * Export the trace file (e.g., `.json` or `.nsys-rep` format) into `results/profiler_trace_phase3/`.

---

## Phase 4: Sequential Context Disaggregation

### Objective
Replicate the concept of "Prefill-Decode Disaggregation" (sharing context caches across independent engines) sequentially on a single GPU to honor tight VRAM constraints.

### Tasks for Agent
1. **Engine A Isolation (Prefill Phase):**
   * Start an independent instance of the inference engine configured with a persistent LMCache backend (e.g., saving to local disk/shared file system).
   * Submit the long context prompt to trigger cache generation.
   * Forcefully shut down Engine A entirely, ensuring all GPU memory (VRAM) is fully released back to the operating system.
2. **Engine B Isolation (Decode Phase):**
   * Start a completely fresh, separate instance of the inference engine (Engine B).
   * Submit a new request containing the exact same prefix context generated by Engine A.
3. **Analysis:**
   * Verify that Engine B successfully locates, deserializes, and injects the KV cache created by Engine A without recalculating the text.
   * Record the TTFT of Engine B to demonstrate that it achieves a "Warm" state instantly, proving that the lifecycle of the KV cache data has been detached from the runtime process that created it.
4. **Output:**
   * Save the sequential migration logs and timing results to `results/disaggregation_phase4.json`.
